# Conventions

## Repository layout
`backend/`, `web/`, `mobile/` (later), `packages/api-client/`. See `steering/tech-stack.md`.

## Backend code layout
- Root package `com.qbits`. Package by feature, not by layer: `sources`, `ingestion`, `relevance`, `stories` (summaries, sections, key terms), `catalog`, `api`.
- Inside a feature: `api` (controllers), `domain` (records, value objects, rules), `service`, `persistence`.
- A feature talks to another only through that feature's `service` classes. No reaching into another feature's `persistence`.

## Java patterns
- Records for DTOs, value objects and config (`@ConfigurationProperties` records under the `qbits.*` prefix).
- Constructor injection only. No field injection, no Lombok.
- `Optional` only as a return type, never as a field or parameter.
- Prefer immutable collections (`List.copyOf`). No `null` returned from public methods.
- Time is `Instant` in UTC everywhere; inject a `Clock` so tests control time.
- Pure logic (normalising, scoring, de-duplication) lives in `domain` with no Spring dependencies.

## REST API shape
- JSON under `/api/v1`. Plural nouns: `/api/v1/items`, `/api/v1/sources`.
- Lists use cursor pagination: `?cursor=<opaque>&limit=<1..100>`, default 20. Response: `{ "data": [...], "nextCursor": "..." | null }`.
- Single resources return the object directly, no envelope.
- Field names in camelCase. Timestamps ISO-8601 UTC (`2026-10-03T06:30:00Z`). IDs are UUIDv7 strings.
- Read endpoints are `GET` only and cacheable; v1 has no public write endpoints.
- The API serves both web and mobile clients, so it returns data, never HTML or layout hints.
- The OpenAPI document generated by springdoc is the contract. A breaking change needs a new version path (`/api/v2`); additive changes are fine in place.
- CORS allows only the configured web origins. No session cookies in v1.

## Front-end code layout (web/, later mobile/)
- Feature folders: `src/features/items/`, `src/features/sources/`. Shared UI in `src/components/`, hooks in `src/hooks/`.
- API calls only through `packages/api-client`. No raw `fetch` to the backend inside components.
- Server state with TanStack Query; local UI state with `useState`. No global store unless a spec asks for one.
- Function components and hooks only. Props typed with `type`, no `any`.
- Files: components `PascalCase.tsx`, hooks `useCamelCase.ts`, everything else `kebab-case.ts`.
- Mobile-first styling with Tailwind; every screen checked at 360px and 1280px wide.
- Article links use `target="_blank" rel="noopener noreferrer"` on web and open in the system browser on mobile.
- Accessibility: semantic HTML, keyboard reachable, visible focus, colour contrast AA.
- Errors: show a plain message and a retry from the Problem Details `title`; never show stack traces or raw JSON.

## Error handling
- Errors use RFC 9457 Problem Details (`application/problem+json`) with an extra `code` field, e.g. `SOURCE_NOT_FOUND`.
- Domain failures throw subclasses of `AppException(code, httpStatus, detail)`. One `@RestControllerAdvice` maps them. Unexpected exceptions become 500 with a generic detail and are logged with a correlation id.
- Never swallow exceptions. Catch only to add context, recover deliberately, or record a failure.
- In ingestion, a failing source is recorded in `source_fetch_log` and the run moves on. One source must never fail the whole run.
- Validate at the edges (config load, request params). Trust data inside the domain.

## Sections
- Domain enum `Section`: `GLOBAL_AI_TECH`, `WORLD_BUSINESS`, `INDIA_AI`, `INNOVATIONS_RESEARCH`.
- API and URL slugs: `global-ai-tech`, `world-business`, `india-ai`, `innovations-research`.
- Display names: "Global AI Tech", "World Business", "India AI", "Innovations & Research". Defined once in the backend and returned by `GET /api/v1/sections`; clients never hard-code them.

## Tabs and windows
- AI Latest is not a `Section` value. It is a 24-hour view over all sections: `GET /api/v1/stories?hours=24`.
- `hours` accepts 1–72; the default is 72. The backend owns both windows; clients only pass the parameter.

## Open-source links
- Type enum `ResourceType`: `CODE`, `MODEL`, `DATASET`, `PAPER`. API values in lower case.
- Canonical URL forms: `https://github.com/{owner}/{repo}`, `https://gitlab.com/{group}/{project}`, `https://huggingface.co/{org}/{model}`, `https://huggingface.co/datasets/{org}/{name}`, `https://huggingface.co/spaces/{org}/{name}` (type `CODE`), `https://arxiv.org/abs/{id}`.
- Labels are fixed strings built from type and host ("Code on GitHub", "Model on Hugging Face", "Paper on arXiv"), never generated text.

## Summary service calls
- Only through the `StoryWriter` interface. No other code calls the provider SDK.
- Prompt text lives in `backend/src/main/resources/prompts/` as versioned files (`story-writer.v1.md`). Each stored story records the prompt version and model name.
- Ask for JSON matching a schema; validate before saving. Invalid output is retried once, then the story is marked `REJECTED` with a reason.
- Tests use `FakeStoryWriter`. Live calls run only in a manual `*LiveIT` suite that needs `ANTHROPIC_API_KEY`.
- Never log prompts, excerpts or model responses at INFO. Log story id, status, tokens and latency.

## Naming
- Classes: `FeedFetcher`, `RelevanceScorer`, `ItemRepository`. Interfaces only when there are two real implementations.
- Tables: snake_case plural (`items`, `sources`, `source_fetch_log`). Columns snake_case. Timestamps end in `_at`.
- Migrations: `V{n}__{short_description}.sql`, never edited after merge.
- Config keys: kebab-case under `qbits.` (`qbits.ingestion.default-interval`).
- Tests: `*Test` for unit, `*IT` for integration (Testcontainers). Test method names describe behaviour: `skipsSourceWhenRobotsDisallows`.

## Logging
- SLF4J with key=value context: `source=techcrunch-ai status=304 durationMs=812`.
- Never log excerpts, article text or prompts. Log URLs, ids and counts only.
- INFO for run summaries, WARN for a degraded source, ERROR for a broken run.

## Testing
- Every task in `tasks.md` ships with its tests in the same change.
- Unit tests for everything in `domain`. Integration tests for repositories and scheduled jobs.
- No network in tests: feeds and robots.txt are served by WireMock from fixtures in `backend/src/test/resources/feeds/`.
- Front end: Vitest + Testing Library for components and hooks, MSW for API responses, Playwright for main flows at phone and desktop widths.
- Each acceptance criterion in `requirements.md` maps to at least one named test. Reference it in a comment: `// 001 R4.2`.

## Commits
- Conventional commits tagged with spec and task: `feat(001/T3): normalise feed excerpts`.
- One task per commit where practical. The full check passes before commit.

## Full check
- Backend: `mvn -f backend/pom.xml verify`
- Web: `npm run verify --workspace web` (type-check, lint, unit tests)
- Run the parts the change touches; run both if the API contract changed.
- `npm run verify` also fails if `packages/api-client/src/schema.ts` does not match `openapi.json`; run `npm run generate:api` after any contract change.
